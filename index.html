FELINUXS · v9.0.0 · Linux

Núcleo de contención
para agentes de IA

Cuando un agente ejecuta algo, ese algo corre encerrado y no puede tocar tu máquina. Y todo queda registrado.

Cuatro cerrojos alrededor de cada ejecución:
VERIFICAR · AUTORIZAR · CONTENER · EVIDENCIAR

124 · 6 · 25 pruebas en verde

01 · El problema

Un agente ejecuta código. Sin control, puede…

Y lo peor: normalmente no queda rastro de qué se ejecutó ni con qué permiso.

👀 Leer

Tus ficheros, tus claves, tu /home, tus secretos.

✍️ Escribir

Modificar o borrar cosas del sistema.

🌐 Salir

Abrir conexiones a internet por su cuenta.

💥 Colgar

Consumir toda la memoria o quedarse en bucle infinito.

02 · La idea

Cuatro cerrojos. Cada uno responde una pregunta.

01

VERIFICAR

¿Es lo que esperaba? Huella sha256. Si cambió → bloquea.

02

AUTORIZAR

¿Tiene permiso? Listas. Red denegada por defecto.

03

CONTENER

¿Dónde corre? En una jaula: sin red, /home invisible.

04

EVIDENCIAR

¿Qué pasó? Registro encadenado por hash.

Modelo honesto: no prometemos prevención perfecta, sino contención a prueba de fallos: aunque el agente lo consiga, no puede comprometer el host.
03 · El viaje de un comando

De la terminal a la jaula y al registro

Escribes el comando — terminal
node dist/cli.js contain -- node -e 'console.log("hola")'
VERIFICAR — core/trust.ts
Huella sha256 vs almacén. Primera vez → fija. Cambió → BLOQUEA.
AUTORIZAR — core/policy.ts
Permitido/prohibido + red deny-by-default. Si dice «no» → no se ejecuta nada.
CONTENER — core/jail.ts (bwrap)
Se fabrica una jaula del SO y el comando corre dentro.
EVIDENCIAR — core/evidence.ts
Registro JSONL encadenado (prev → hash). Append-only.
04 · La jaula, por dentro y por fuera

El mismo comando, dos realidades

FUERA — el host (tu máquina)

Ficheros personalesvisibles
Red / internetdisponible
Sistema (/usr)escribible
Nombre del equiporeal
Poderes (capabilities)según usuario

Aquí vive lo que quieres proteger.

DENTRO — la jaula (bwrap)

Datos de /homeVACÍO
Red / internetSIN RED (ENETUNREACH)
Sistema (/usr)solo-lectura
Hostnamefelinuxs-sandbox
CapabilitiesNINGUNA (cap-drop ALL)

Aquí corre el código del agente. Aunque quiera, no toca lo de la izquierda.

Sin jaula no se ejecuta. Si bwrap falta, contain devuelve 126 y no lanza nada. Sin «ejecuto sin jaula y disimulo».

05c · Anatomía de un registro

El eslabón que hace la cadena

{
  "seq": 1,
  "ts": "2026-10-20T00:08:28.116Z",
  "id": "contain",
  "decision": "allowed",
  "backend": "bwrap",
  "steps": {
    "verify":   { "status": "off" },
    "authorize":{ "allowNet": false, "memMb": 128 },
    "contain":  { "ok": true, "exitCode": 0 }
  },
  "prev": "GENESIS",
  "hash": "e1b9e7a50d1d…"
}

prev + hash

Cada registro guarda el hash del anterior. Eso forma una cadena: cambiar uno rompe todos los siguientes.

steps por verbo

Queda constancia de cada cerrojo: si se verificó, si se autorizó (y con qué límites) y si se contuvo.

Append-only

Entre ejecuciones la cadena continúa (seq 1→2…); nunca se reinicia.

07 · Arquitectura de carpetas

Dónde vive cada pieza

felinuxs/ ├─ src/ │ ├─ core/ ★ EL NÚCLEO (sin MCP) │ │ ├─ trust.ts VERIFICAR │ │ ├─ policy.ts AUTORIZAR │ │ ├─ jail.ts CONTENER (bwrap) │ │ ├─ evidence.ts EVIDENCIAR (hash-chain) │ │ ├─ containment.ts fachada V·A·C·E │ │ ├─ contain-cli.ts puerta "contain" │ │ ├─ evidence-cli.tspuerta "evidence" │ │ └─ selftest.ts 25 casos │ ├─ mcp/ puerta MCP (una más) │ │ ├─ host.ts hospeda servidores → los contiene │ │ ├─ upstream.ts cliente de 1 servidor (en jaula) │ │ ├─ protocol.ts tipos + config (incl. "jail") │ │ └─ discovery.ts descubrimiento local │ ├─ kernel/ tools, blockchain, P2P (opcional) │ ├─ fixtures/ servidores de prueba (echo, probe) │ ├─ cli.ts punto de entrada │ └─ selftest.ts batería end-to-end (124) ├─ docs/ blueprint, límites, ESTA presentación ├─ pentest/ ataques reproducibles ├─ pruebas/ logs fechados de cada pasada ├─ BITACORA.md paso a paso del proceso └─ probar.sh batería completa (4 suites)

El núcleo es lo que vende

src/core/ funciona sin MCP: es una función central del motor, no una capacidad suelta de un protocolo.

MCP es solo una puerta

src/mcp/ habla MCP, pero los servidores de terceros se lanzan dentro de la jaula del núcleo.

El kernel es opcional

src/kernel/ (tools, blockchain, P2P) se conserva, pero el producto es el núcleo + host.

08 · Lo honesto (lo que NO es)

Esta diapositiva existe para no vender humo

🟡 Debilidad conocida (A3/A4)

El verificador por regex se puede evadir. No se «arregla» con más regex: se deja de depender de él. El ataque queda confinado por la jaula.

🔒 Alcance

Contención del espacio de usuario (namespaces de Linux). No cubre vulnerabilidades del kernel ni canales laterales.

🧩 No lo inventamos

bwrap, namespaces, jaulas, seccomp… ya existían. El aporte es la arquitectura integrada con MCP como una puerta más.

📊 Nivel de garantía

Evidencia inicial demostrada por pruebas, no un certificado de producción. Fail-safe, no prevención perfecta.
